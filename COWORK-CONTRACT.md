# Cowork integration contract (implementation working agreement)

- Bridge `http://127.0.0.1:3091`, `Authorization: Bearer <agent token>`.
- POST `/v1/tool`: `{protocolVersion:1,requestId,sessionId,tool,arguments}`. response `{protocolVersion:1,requestId,ok:true,result}` or `{protocolVersion:1,requestId,ok:false,error:{code,message}}`.
- Agent tools: `phone.status`, `phone.apps`, `phone.start`, `phone.screenshot`, `phone.ui_tree`, `phone.tap`, `phone.long_press`, `phone.swipe`, `phone.scroll`, `phone.read_page`, `phone.type_text`, `phone.key`, `phone.wait`, `phone.gesture`, `phone.launch_app`, `phone.pause`, `phone.stop`, `phone.request_intervention`.
- A refusal is not a session end: refusals raised before input is injected (`NODE_STALE`, `STALE_OBSERVATION`, `ARGUMENTS_INVALID`, `KEY_DENIED`, `INVALID_GESTURE`, `WAIT_LIMIT`, `SCROLL_UNSUPPORTED`, `INPUT_REJECTED`, `LAUNCH_TIMEOUT`, `SCREEN_SETTLING`) keep the workspace running and tell the model what to do next. Only a boundary violation (`Foreign task on profile display`, unapproved package, identity/security failure, `LOCKED`, `USER_CONTROL`, `APP_CONFLICT`, task stop) pauses or ends it. The workspace watchdog tolerates a screen that is transitioning for up to 20 s before it pauses as `SCREEN_UNRESPONSIVE`.
- Standing display: the broker creates the AI virtual display once and keeps it between turns; a turn claims it on its first tool call (`phone.start` is optional and `packageName` may be omitted), and turn end/stop only clears its content. `status.workspaceActive` tells whether a turn currently owns it. `phone.ui_tree` on an empty screen returns an empty tree; `phone.launch_app` needs no prior observation.
- `phone.start`/`phone.launch_app` wait up to 10 s for the app window; on `LAUNCH_TIMEOUT` the owned display and the started activity are kept, so the model calls `phone.wait` and observes again instead of starting over. System dialog hosts (permission controller, installer, OEM `com.oplus.*` dialogs) count as "app is up" for that wait.
- Screenshot gate: `phone.screenshot` is refused with error `TREE_REQUIRED` (message in `TREE_REQUIRED_MESSAGE`) unless `phone.ui_tree` was read for the current screen (a tree that returned `complete:false` also unlocks screenshots, because the tree itself says to look at pixels). Enforced twice and independently: `BrokerClient` in the plugin (per session; any non-observation tool renews the requirement for all sessions) and the native broker (`treeRead`, reset by every input, `phone.wait`, `phone.start`, hand-over/hand-back and workspace close).
- Mutations require a short-lived `observationId`; coordinate actions consume it, `elementId` actions verify the bound `phone_ui_tree` observation instead (a screenshot taken between the tree and the tap does not invalidate the element ids). A refusal raised before any event was injected (argument/element validation) keeps the observation so the model can retry or fall back to coordinates. No main-display target accepted. `phone.key` supports the display's own virtual keys: BACK and ENTER (display-local key events, observation required), HOME (opens the profile-owned `dev.dsh.pocket.isolation/.HomeActivity` AI desktop; the app keeps running in the background) and RECENTS (returns the work-profile tasks on the owned display as `note` without changing the screen). HOME and RECENTS need no observation, and `phone.launch_app` needs none when switching back to a backgrounded app. `phone.launch_app` packageName only allowlist. start session locked to authoritative DSH sessionId. No arbitrary intents/code/commands.
- Separate user controller token is never exposed as a model tool. Agent cannot resume/approve. Controller `/v1/control` manages start/approve/pause/resume/stop and allowlist after explicit user action.
- `/v1/events?after=<revision>` returns bounded redacted execution events. `/v1/state` carries a native `activity` object `{seq,app,text,events:[{id,text}]}` (key-action activity for the island, no model call).
- IslandRuntime follows state events. Main-display environment supplied by broker read-only window observer; fail closed for unknown/stale/locked. No automatic permission grants.
- New Android broker package `dev.dsh.pocket.cowork.broker`, started by fixed root app_process entrypoint from installed APK. UI integration handled by lead. Subagents edit only their delegated folders; lead adapts interfaces after completion if message delivery unsupported.
