# Cowork 与任务岛实施设计

> **需求更新：** 用户要求自由使用主屏时，后台副屏持续工作。当前安装版的主屏变化暂停和同包拒绝不满足该目标；不能将这些现有限制当成最终使用前提。后续隔离候选、只读实机能力记录和验收条件见[主屏与后台并行设计](<cowork-concurrent-design.md>)。新架构尚未实机通过，本页其余内容描述现有实现。

## 目标与不可放宽的边界

Cowork 是受约束的手机助手，不是隐藏了 Shell 按钮的 Code。仅开放基础联网、授权目录文件工具和副屏操作。后端工具限制与执行守卫共同拒绝 Shell、任意代码、包管理、MCP、代理委派及未知工具。不能通过普通文件工具改写 DSH 配置、插件、凭据或服务入口。

手机当前 DSH 是 root chroot；本实现是能力隔离，不声称是可抵御任意本机 root 程序的沙箱。现有 Code 权限不扩大，Cowork 无自动升级权限路径。

## 组件

1. DSH `cowork` preset：严格工具目录、执行守卫、有限文件服务与网络入口；绑定真实会话 ID 调用手机桥。
2. 原生手机 broker：固定 Java 入口运行于 Android Runtime，创建自己持有的 VirtualDisplay；通过 UiAutomation 获取各显示窗口和节点，通过目标 display 的输入事件操作。外部只见严格 JSON 协议，不暴露命令执行。
3. 策略层：显示所有权、应用允许名单、主副屏冲突、观察版本、单次消费、用户中止与审批状态。
4. DSH Pocket：显式启用控制服务、任务岛、审批/接管界面、通知回退与权限说明。
5. 任务岛活动：由 broker 原生产生关键操作活动（`/v1/state` 的 `activity`），不调用模型。

## 副屏工具

`phone.status/apps/start/screenshot/ui_tree/tap/long_press/swipe/scroll/type_text/key/wait/launch_app/pause/stop/request_intervention`。启动只接受包名，输入工具不接受 displayId；display 只能是 broker 自己创建的非主屏实例。每次截图或元素树观察生成短期 observationId，变化、超时、使用一次均失效。密码字段与安全窗口不可读；不把读不到副屏退回到主屏。

元素树使用系统可访问性 API，不是 OCR。自绘控件可能缺少节点。中文输入先使用可访问性 ACTION_SET_TEXT 对非密码可编辑节点定向设置；不使用共享剪贴板。原始手势仅在观察与前台窗口核对成功后执行。完成注入不等于任务成功，工具返回执行结果并要求重新观察。

重要操作先进入用户介入：支付/账号授权/安装/密码步骤不自动提交。未知或无法可靠分类的交互保守交给用户。用户控制通道使用独立 secret，Agent token 没有审批/恢复权限。审批绑定动作描述、会话和屏幕版本，不允许模型审批自己。

## 任务岛

主屏顶部小胶囊，非焦点窗口，触摸范围局限于胶囊。点开可查看状态、最近步骤、暂停和停止。游戏/自定义排除名单、锁屏及不可靠前台识别默认退回持续通知。权限由用户通过系统界面授予，不通过 root 强制开启悬浮窗。

真实执行状态由 broker 决定：执行中、等待用户、安全暂停、完成/失败；任务岛显示 broker 原生的关键操作活动（不含密码、完整屏幕、完整聊天或推理），不使用模型摘要；网页和屏幕文本视为不可信数据。

暂停/停止直接撤销执行能力，不通过主 Agent 对话。正在发送给系统的一次触摸无法撤回，但队列不再提交后续动作。用户接管期间隐藏敏感观察并停止 Agent 输入。

## 实施与验证顺序

先离线协议/策略测试，再单独测试 broker 能否在当前 ROM 创建/销毁自己的显示、读副屏节点和注入目标输入；只用无网络、无敏感数据的测试 App。通过后接入 Cowork preset 与任务岛，再用独立测试清单检查每个工具的正向、拒绝、失效、超时与中止路径。

主屏上的操作及系统权限需用户参与。测试完成回收自有副屏，并通过 SurfaceFlinger 核对无遗留显示。不能以单元测试代替真机证据，也不能以状态查询成功代替压缩/操作全链路成功。
